Suggesting the swing set's structural inputs

A new swing set opens with up to 14 fields marked "Input needed", and a copied project asks for the same values to be confirmed. Most of them a beginner cannot know. Hard rule 3 forbids hidden structural defaults; M8 already let the record cabinet suggest its moisture range and deflection limit from a cited source the owner checks. This page lists every swing set input with what Kerf could do instead, then asks how hard rule 3 should read and how project status is set.

What to decide

  1. How hard rule 3 applies: R-A (suggested) suggestions from a named source or stated rule of thumb, confirmed in one step, or R-B questions only, no suggested values.
  2. Each row in the table below: take the proposal, or say which you want instead.
  3. Project status: S-2 (suggested) inferred, with a hand override in the project, S-1 inferred only, or S-3 by hand only.

Every input, and what Kerf could do instead

Three kinds of answer: Suggest a value with its source, shown as a suggestion until confirmed; Ask a plain question and derive the value; Enter, with the reason no suggestion is honest. A row marked "source to verify" names where the value would come from but has not been checked against the source yet (hard rule 5); it would be checked in the implementation issue before any number ships.

InputProposalBasis
Beam species and gradeEnter, at the store: a shopping-list line "Read the grade stamp on the beam boards" that opens this field, with a drawing of a grade stamp.Only the boards bought say it; no source gives a regional default.
Whether the beam is incisedAsk at the store beside the grade stamp: "Do the faces have rows of small slits?"NDS applies Ci to incised dimension lumber (AWC FAQ); whether a board is incised is seen, not inferred.
Beam moisture contentAsk "Will the beam stand outdoors, uncovered?" Yes means wet service; Suggest the value used for the beam's own weight from that answer (source to verify: Wood Handbook density with moisture content).NDS CM applies where moisture stays above 19% in service; AWC: assume the worst when in doubt, and deck span tables assume wet service.
Deflection limitSuggest 240 (span / 240), as the cabinet does for its shelves.IBC Table 1604.3 uses L/240 for floor members under dead plus live load. A swing beam is not listed, so the plan says it is borrowed from the closest member type.
Hanger ratingEnter, at the store: a shopping-list line "Read the rated load on the hanger package".A manufacturer's rating; Kerf never stands in for one (non-goals).
Heaviest rider, left and rightEnter (already asked in the starting questions).Only the owner knows who will swing.
Maximum swing angleSuggest 90°, the chains level with the beam.The largest angle Kerf's pendulum model takes, so the largest load it gives (factor 3 − 2 cos θ = 3); a stated bound, not a guess at how high the kids swing.
Dynamic factorEnter, with an experienced builder (unchanged), with the help saying what the factor stands for.No published value found for swing snap loads (searched November 2026: forums and vendor pages only). A guess here would be a hidden default in effect.
Leg-to-beam bolt diameter and countSuggest the size the template's bolt layout check (0016) fits for the chosen stock, labeled "fits the NDS spacing for a 4x6 beam; confirm with an experienced builder".The check already knows which diameters fit; source to verify for the starting size (common A-frame hardware).
Crossbar and gusset bolts, diameter and countSame as the leg bolts.Same.
Ply bolts (built-up beam only)Suggest diameter and count from a published built-up beam fastening schedule (source to verify).Decision 0013 checks plies one by one; the schedule would set the starting count.
Ground anchors per foot (on pads only)Enter, from the anchor maker's instructions.Anchoring is a checklist item, not a calculation (non-goals).

With these, a new swing set opens with four questions at the store (stamp, slits, hanger rating, and, on pads, anchors) and three for the owner (two riders and the dynamic factor), instead of 14 empty fields.

How hard rule 3 would read

R-A · Suggest from a source, confirm in one stepSuggested

"Structural inputs are entered or confirmed by the owner. Kerf may suggest one from a named source and edition or a stated rule of thumb, shown as a suggestion with its basis until the owner confirms it; a check never runs on an unconfirmed suggestion as if it were confirmed." Amends AGENTS.md rule 3 and 0001, matching what M8 allowed for the cabinet.

R-B · Questions only

Rule 3 stays as written. Kerf asks plain questions and derives values only from the answers (the moisture question above), never offers a number from a source. Leaves the deflection limit, swing angle, and bolts empty.

Either way a missing input still reads "Input needed", and margins still say "under these assumptions".

Project status

Status is already inferred on the server: the first tick moves a Planned project to In progress, and finishing the last step moves it to Built; it never moves back (ARCHITECTURE, PATCH /progress). The dropdown on the projects list is the hand override, and it is the only place the owner sees status change.

S-1 · Inferred only

Status becomes a label everywhere; no way to set it. A project built without ticking steps stays In progress.

S-2 · Inferred, with an override in the projectSuggested

The list shows a label (#357); the project's Edit screen keeps a Status field for "we built it without the app" or "shelved".

S-3 · By hand only

Remove the inference. Every change is the owner's.
