Tool icons

A small icon for each tool type in the library (#85), shown beside the tool's name in the tool list, in each method's list of tools, and in Building mode. No open-license set covers woodworking tools: Lucide, for example, has a drill, a hammer, and a shovel, but no saw, clamp, or level. So Kerf draws its own, in the repo, as it does its other icons (#79).

This page draws three directions on the same 10 tools, chosen to include the pairs most easily confused: two saws, two squares, and two drivers. Each tool is drawn once; the directions differ only in what is filled. The panels use Kerf's C1 colors (#43) and Atkinson Hyperlegible Next (#42).

Choices for the owner

  1. Direction: A outline, B outline with the working part filled, or C silhouette. Suggested: B.
  2. Grid: draw tool icons on a 24-unit grid, with strokes of 2.4 units so they match the existing 16-unit icons' weight at any size. Suggested: yes.
  3. Where they appear: the tool list (each tool's heading and the Add buttons), the Tools line of every method in the plan, and Building mode. Always beside the tool's name, never alone. Suggested: all three.

Once a direction is chosen, the other 14 tools are drawn in it, the icons go into apps/web/src/ui keyed by tool-type ID, and the choice is recorded in docs/design/README.md.

Common to all three

What every direction does

  • The name is always beside the icon. NN/g found that only a few icons (home, print, search) are recognized without words, so an icon needs a visible text label. Here the icon helps you find a tool in a list; the name says what it is. The icon is hidden from screen readers, as Kerf's other icons are (#43, rule 6).
  • One drawing per tool, one weight, one view. Each tool is drawn side-on, flat, with round caps and joins, on a 24-unit grid with at least one unit of space at the edges. Apple's guidelines ask for one size, level of detail, stroke weight, and perspective across a set.
  • The same weight as Kerf's icons now. The flag, done, and error icons are drawn on a 16-unit grid with 1.6-unit strokes, the diagrams' visible-line weight (#44). Tools need more detail than 16 units allow, so they use 24 units with 2.4-unit strokes: the same line at any size.
  • One color. Each icon is drawn in the text color, so it prints in black and reads the same in grayscale and in dark mode.
  • No brands. Generic tool shapes only (hard rule 11).

Critique

Against the criteria in #86

Judged on this page, at the sizes shown. Nobody but the owner has seen these yet; a real check is naming them with the names hidden (the button above), and again in the garage (#69).

Suggested: B. It keeps A's line and match with Kerf's icons and diagrams, and the filled working part is what tells similar tools apart at 16 px, the size where A fails. C is the boldest at a distance but loses the inner shapes that separate tools, and would be the only filled style in the app.

For the chosen direction

Construction guide

Written for B; for A or C, only the fill rule changes. It goes into docs/design/system.md with the set, so tools added later match.

  • Grid: 24 × 24 units, artwork inside a one-unit margin.
  • Stroke: 2.4 units, round caps and joins, centered. One weight for every line.
  • View: side-on and flat, no perspective; long tools (chisel) at 45°.
  • Fill: only the part that cuts, holds, measures, or drives, in the text color. Holes and marks on a filled part are cut out in the background color.
  • Corners: 0.5 to 1.2 units on rectangles; 2 units or more between separate parts so they do not merge at 16 px.
  • Size in use: 20 px beside desk text, 24 px in shop density, about 14 px in print. Always beside the tool's name, hidden from screen readers.
  • Code: one component in apps/web/src/ui keyed by tool-type ID, shown on the catalog page.

Precedents and guidance

Sources

Checked in October 2026.

Labels

NN/g: few icons are recognized universally (home, print, search), so a text label should sit beside an icon, visible without hovering. If it takes more than about five seconds to think of an icon for something, the icon will not say it alone. Test icons by asking people what they expect each to mean.

Icon Usability

A consistent set

Apple Human Interface Guidelines: highly simplified designs; one size, level of detail, stroke weight, and perspective across an app's icons; icon weight matched to the text beside it; alternative text for custom icons.

Icons · SF Symbols

Grids and strokes

Material Design's system icons: a 24 dp grid, keyline shapes, and one 2 dp stroke throughout. Lucide: a 24 × 24 canvas, at least 1 px of padding, 2 px round-capped strokes, and 2 px between separate elements.

Material: system icons · Lucide: design principles

Open sets

Lucide has drill, hammer, shovel, ruler, and wrench, but no saw, clamp, or level (checked in its repository, October 2026). Its style is close to A.

lucide-icons/lucide

Testing symbols

ANSI Z535.3 sets 85% correct understanding, with under 5% critical confusions, as the bar for a safety symbol used without words. Tool icons here always have their name, so they need not meet it; it shows how far an unlabeled pictogram has to go.

CPSC: symbol comprehension study (Z535.3 criteria)
