Kerf · Design milestone · Issue #42

Typography

Numbers are most of what Kerf shows, so this stage is mostly about numbers: which typeface, how big at each distance, how fractions to 1/16 are set, and how lengths, angles, and margins line up. It builds on #41's two densities: desk for the plan, and shop inside Shopping and Building, with a read size for 0.5 m and a glance size for 1.0 m.

Each direction below is set in its real typeface at its real size. The sizes come from measuring each font's digits, not from a rule of thumb.

What I need from you

Four choices. My suggestion is first in each. A reply like T2, slash fractions, add the font, x is enough.

  1. Typeface: T2 Atkinson Hyperlegible, T3 B612, or T1 the system font.
  2. Fractions: full-size slash (138-3/8"), built-in diagonal fractions, or enlarged fractions.
  3. Adding the font: T2 and T3 are web fonts, which is a new dependency. May I self-host the font files in apps/web?
  4. The margin sign: keep margin 1.1x as AGENTS.md writes it, or use the multiplication sign, margin 1.1×.

Best judged in the garage: open this page on your phone, prop it where you would, and use the blur and dimming controls on the specimens.

Measured, not assumed

What each candidate's digits measure

Measured from each font's own files with fontTools. "Digit height" is the height of an 8 as a share of the font size: the larger it is, the smaller the font size needed for the same legibility. The glance and read sizes put a digit at 20 arc-minutes from 1.0 m and 16 arc-minutes from 0.5 m on a phone (#41).

Evidence for the use
Designed by Applied Design Works with the Braille Institute, with low-vision specialists, so that every character is as distinct as possible: I has serifs, 1 and l differ, F and E differ, shapes are exaggerated. Poor light and a dusty screen are a mild version of low vision.
Hierarchy
A variable font from 200 to 800, so labels, body, and numbers can each take their own weight. Tabular figures and fractions on request; a matching Mono for formulas.
Cost
The smallest digits of the three for a given size (0.694), so glance numbers need 51 px. Its open, rounded shapes read as friendly rather than technical.

Evidence for the use
Commissioned by Airbus from Intactile Design, with research by ENAC and the University of Toulouse, for cockpit screens in degraded conditions: vibration, glare, fatigue. Released as open source in 2017.
Numbers
The tallest digits of the candidates (0.767), so glance numbers need only 46 px, and digits are tabular by default. It reads like an instrument, which suits a tool that measures.
Cost
Two weights only, so hierarchy rests on size. No fractions feature, which does not matter with slash fractions. Wide letters make long text, such as method steps, take more lines.

Suggestion

T2, Atkinson Hyperlegible Next for everything, with tabular figures for numbers and the Mono for formulas. The research behind it matches the garage (reading in poor conditions), its range of weights gives the hierarchy that the plan document needs, and it costs 45 KB. B612 is the close second and the better choice if you want the numbers to read like an instrument; run the blur test on both before deciding.

Fractions

How 138-3/8" is set

Fractions to 1/16 are where a misread costs a board. The question is whether they keep full-size digits. Measured in SF Pro and IBM Plex, the digits inside a built-in diagonal fraction are about half the height of a full digit.

Full-size slashSuggested
138-3/8"

As core formats it today. Every digit is full size: at glance size about 20 arc-minutes from 1.0 m. Fits a phone at the glance size in every candidate.

Diagonal fraction (OpenType)
138 3/8"

Typographically traditional, and compact. Fraction digits are about half height: about 10 arc-minutes at glance size, under the 16-minute minimum, and about 6 px tall in a 17 px table. 3/8 and 5/8 become hard to tell apart.

Enlarged fraction
138 3/8"

The whole number stands out from the fraction, which helps scanning. Fraction digits at 70% are about 14 arc-minutes at glance size, still under the minimum. Needs core to return the parts of a length rather than one string.

Dependency

Adding the font

AGENTS.md asks for permission before any dependency. For T2 the proposal is:

Self-host two filesSuggested

Atkinson Hyperlegible Next (variable, 30 KB) and Mono (15 KB), Latin subset, as woff2 in apps/web, with the OFL license file beside them. No package and no request to Google, so nothing leaves the owner's devices and the font is there whenever the app is. Version and source recorded in a decision record.

A package

An npm package such as Fontsource's. Easier to update, but a package dependency for two static files.

Google Fonts link

Simplest, but every page load asks a third party for the font, and the font is missing if that request fails.

New requirements

What this stage adds

None with the suggested choices: core's formatters already produce full-size slash fractions and straight marks. Enlarged fractions or hyphen-aligned columns would need core to return a length's parts, and the cut list stores formatted strings in the snapshot, so either would mean a snapshot shape change (0014).

Numbers come from packages/core/src/templates/swing-set-a-frame/snapshots/v2.json, example 1, through core's formatters. Kept at docs/design/typography.html; choices are recorded in docs/design/README.md. The specimens load the candidate fonts from Google Fonts for review only.
